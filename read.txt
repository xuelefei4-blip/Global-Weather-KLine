                    Global Meteorology Monitor & MeteoOps 架构说明

根目录结构 (D:\温度K值 (GITHUB)\)/
│
├── MeteoOps/                  # [后端运维控制台] Python 自动化数据管道工具箱
│   ├── step1_detect_align.py  # 步骤1：探测路径与底库对齐检测
│   ├── step2_history_sync.py  # 步骤2：补齐十年历史数据 (2015~2025 单城串行闭环)
│   ├── step3_realtime_sync.py # 步骤3：同步 2026 最新实况与预测数据
│   ├── step4_scaffold_city.py # 步骤4：选城建仓 (随机/手选，建目录与写索引)
│   ├── step5_export_updates.py# 步骤5：导出本次更新与新增明细账目
│   ├── step6_audit_repair.py  # 步骤6：全库质检与自动修复 (路径、空文件、ID对齐)
│   ├── coverage.html          # 后台运维控制台的可视化操作大屏
│   └── server.py              # 后台本地 HTTP 服务调度支持
│
└── MeteoSystem/               # [前端可视化大屏] 纯静态气象 K 线监控系统
    ├── kline.html             # [核心主界面] 单城市气象K线监控大屏
    │                          # (3D地球仪、像素仓鼠、H/D/W/M/Y多周期切换、湿度曲线、双皮肤)
    ├── lab.html               # [核心对比室] 双城市气象K线同屏对比实验室
    │                          # (支持两座城市同屏独立选周期、独立时区时钟对比)
    └── static/                # 静态资源库 (核心样式、数据与媒体)
        ├── css/
        │   └── style.css      # 全局样式表 (支持黑夜/明亮双皮肤换肤与响应式布局)
        ├── images/            # 贴图与素材 (地球仪地表贴图、像素仓鼠)
        └── data/              # 全球气象历史数据库 (按大洲/国家/城市分片存储)
            ├── index.json     # 全球顶级大洲索引
            ├── Asia/          # 亚洲数据 (包含城市子目录及按年分片的 JSON)
            ├── Europe/        # 欧洲数据
            ├── North_America/ # 北美洲数据
            ├── Oceania/       # 大洋洲数据
            ├── South_America/ # 南美洲数据
            └── Africa/        # 非洲数据

================================================================================
【全栈架构协同原则】：
1. 后端管治安检 (MeteoOps)：
   通过 Python 脚本流水线完成 161 座全球城市的建仓、历史抓取、实况同步、质检修复，
   确保底层 JSON 数据的绝对健康与原子级完整。

2. 前端展示渲染 (MeteoSystem)：
   零后端侵入，纯浏览器端通过 Lightweight Charts 异步拉取 `static/data/` 中的
   OHLCV 分片切片进行高性能 K 线渲染与 3D 地球仪联动。
